# UI-Driven Question Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user get a real question (e.g. pasted from Teams) into the system from the web UI — upload a `.txt`/`.md` file or paste text into a Chat-tab panel, click Run, and have it processed through the exact same `build_graph()` pipeline `run_local.py` already uses.

**Architecture:** One new business-logic module (`assistant/ingest.py`, mirroring how `kb.py`/`tasks.py`/`chat.py` hold logic while `web/app.py` stays a thin JSON adapter), one new endpoint, one new frontend panel. No new pipeline logic — pure reuse of `build_graph()`, `redact()`, and the existing `raw_documents` table.

**Tech Stack:** Same as the rest of `assistant/` — psycopg, FastAPI, vanilla JS. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-07-22-ui-ingest-design.md`

## Global Constraints

- Dedup is content-hash based: `sha256(raw_text)` (the RAW text, before redaction) checked against `raw_documents.file_hash`.
- **Ordering matters**: `build_graph().invoke(...)` runs BEFORE the `raw_documents` insert. If the graph call raises, nothing is recorded, so retrying the same text re-runs the graph instead of falsely reporting `"duplicate"` — same rule as `resolve_escalation`'s learn-before-mark-resolved.
- `raw_documents.body` stores the REDACTED text, never raw PII.
- `sender` is always `"unknown"`, `thread_id` is always `None` — no extraction in this pass.
- Empty/whitespace-only input is rejected with HTTP 400 at the API boundary (in the route, before `ingest_text` is called) — `ingest_text` itself does not re-check this.
- No `.eml`/`.pdf`/`.msg` parsing, no drop-folder/watcher, no batch import — one text submission per call, file and paste both resolve to plain text client-side before the request is sent.

"""Turn a raw piece of text (uploaded or pasted in the web UI) into a
processed question — reuses the exact same pipeline run_local.py uses.

Ordering is deliberate: build_graph() runs BEFORE the raw_documents insert.
If the graph call raises, nothing is recorded, so retrying the same text
re-runs the graph instead of falsely reporting "duplicate" — same rule as
tasks.py's resolve_escalation (risky step first, durable record only after
it succeeds).
"""
import hashlib

from assistant.db.client import get_connection
from assistant.graph import build_graph
from assistant.redact import redact


def _hash(raw_text: str) -> str:
    return hashlib.sha256(raw_text.encode()).hexdigest()


def ingest_text(raw_text: str, source: str = "web-import") -> dict:
    file_hash = _hash(raw_text)
    with get_connection() as conn:
        existing = conn.execute(
            "SELECT id FROM raw_documents WHERE file_hash=%s", (file_hash,)
        ).fetchone()
    if existing is not None:
        return {"status": "duplicate", "raw_document_id": existing[0]}

    out = build_graph().invoke(
        {"raw_text": raw_text, "source_channel": source, "sender": "unknown", "thread_id": None}
    )

    redacted, _ = redact(raw_text)
    with get_connection() as conn:
        row = conn.execute(
            "INSERT INTO raw_documents (source, sender, thread_id, body, file_hash)"
            " VALUES (%s, %s, %s, %s, %s) RETURNING id",
            (source, "unknown", None, redacted, file_hash),
        ).fetchone()

    if out.get("escalation_id"):
        return {"status": "escalated", "escalation_id": out["escalation_id"], "raw_document_id": row[0]}
    return {"status": "drafted", "review_item_id": out["review_item_id"], "raw_document_id": row[0]}
```

async function runImport() {
  const fileInput = document.getElementById('import-file');
  const textArea = document.getElementById('import-text');
  const resultDiv = document.getElementById('import-result');
  resultDiv.innerHTML = '';

  let text;
  if (fileInput.files.length) {
    text = await fileInput.files[0].text();
  } else {
    text = textArea.value.trim();
  }
  if (!text) {
    resultDiv.innerHTML = '<span class="error">Choose a file or paste some text first.</span>';
    return;
  }

  try {
    const data = await api('POST', '/api/ingest', {text});
    let label;
    if (data.status === 'duplicate') label = 'Already processed before.';
    else if (data.status === 'escalated') label = `Escalated — check Tasks (#${data.escalation_id}).`;
    else label = `Drafted a reply — check Tasks (#${data.review_item_id}).`;
    resultDiv.innerHTML = `<div class="settled">${esc(label)}</div>`;
    fileInput.value = '';
    textArea.value = '';
    _lastTasksJson = '';
    loadTasks();
  } catch (e) {
    resultDiv.innerHTML = '<span class="error">' + esc(e.message) + '</span>';
  }
}
```

## Definition of done (this plan)

From the web UI's Chat tab, expanding "Import a question" and either pasting text or choosing a `.txt`/`.md` file, then clicking Run, processes it through the real `build_graph()` pipeline and the result (escalated/drafted/duplicate) appears in Tasks — verified live, not just via tests. Resubmitting identical text is correctly recognized as a duplicate and does not create a second Tasks entry. A failed graph call does not block a subsequent retry of the same text.
